# PCIe-GPIO-I2C — 用研华 PCIE-1751 的普通 GPIO 模拟 I²C 通信

本项目在 PC 上位机侧，利用研华 **PCIE-1751**（48 路 5V/TTL 数字 I/O + 3 路计数器，PCI Express 接口）的**普通数字 I/O 引脚**，以软件位操作（bit-banging）的方式模拟 I²C 主机时序，从而驱动挂在板卡外部的 I²C 从设备。

板卡本身**不含 I²C 控制器**：START / STOP / 位时钟、字节收发、ACK/NACK 判读全部由上位机程序按 I²C 协议逐位产生和采样。

## 信号链路

```
   上位机程序                PCIE-1751              H-9220 背板
 ┌──────────────┐        ┌─────────────┐        ┌──────────────┐        ┌────────┐
 │ I²C 位时序生成 │DAQNavi │  48-ch DIO  │ SCL    │              │        │        │
 │ START/ACK/…  │───────►│  5V TTL 推挽 │═══════►│  DS2482-100  │ 1-Wire │ DS2431 │
 │ DS2482 命令层 │        │             │ SDA_OUT│  U31  @0x18  │═══════►│ EEPROM │
 │ DS2431 协议层 │◄───────│  P2_6/P2_7  │◄═══════│  I²C ↔ 1-Wire │ ID_BD  │        │
 └──────────────┘        │  P0_2       │ SDA_IN │              │        │        │
                         └─────────────┘        └──────────────┘        └────────┘
                            J2 / SCSI-68      SCL、SDA 各经 2.2k 上拉至 +5V
```

## 为什么必须"模拟"

| I²C 的要求 | PCIE-1751 提供的能力 | 本项目的处理方式 |
|------------|----------------------|------------------|
| SDA/SCL 为**开漏**输出，靠外部上拉产生高电平 | 5V/TTL **推挽**输出（Sink 24 mA @0.4 V，Source 15 mA @2.4 V） | 用「输出 0」表示拉低，用「切换为输入（高阻）」表示释放，外接上拉电阻产生高电平 |
| 主机需读回 SDA 以采样数据和 ACK | 每个引脚均可作为输入读取 | 背板已把 SDA 单独引出一路到输入脚 `P0_2`，读回不必动方向 |
| 需要按**位**切换方向 | 端口方向按**半字节（4 bit）**配置（每个 8 位端口分高/低两个 nibble，软件可配） | SDA 的驱动脚需独占一个 nibble——现有接线不满足，见下文「半字节方向冲突」 |
| 硬件定时产生位时钟 | 无 I²C 外设，只能由软件调用触发 PCIe 事务 | 软件循环生成时序，运行在远低于 100 kHz 的速率上 |

PCIE-1751 模拟 8255 PPI 的 mode 0，6 个 8 位端口 P0~P5，每个端口的高/低半字节可分别配置为输入或输出——这是能够模拟开漏的前提。

## 实际接线（H-9220 背板 REV07）

I²C 从设备为背板上的 **DS2482S-100+**（U31），上拉电阻 R35 / R36 均为 **2.2 kΩ 接 +5 V**，已在背板上，无需外加。

| 网络名 | J2（SCSI-68）引脚 | PCIE-1751 端口位 | 所属半字节 | 用途 |
|--------|-------------------|------------------|------------|------|
| `I2C_SCL` | 25 | `P2_6` | Port 2 **高**半字节（bit4~7） | PC 输出时钟 |
| `I2C_SDA_OUT` | 26 | `P2_7` | Port 2 **高**半字节（bit4~7） | PC 驱动 SDA |
| `I2C_SDA_IN` | 3 | `P0_2` | Port 0 低半字节（bit0~3） | PC 读回 SDA |
| `GND` | 27 | GND | — | 共地 |

**SDA 是一根线、两个引脚**：`I2C_SDA_IN` 与 `I2C_SDA_OUT` 在 DS2482 的 SDA 节点上是**同一个电气节点**（原理图中同一根导线上挂了两个网络标号），只是分别引到板卡的一个输出脚和一个输入脚。因此 P0_2 只读、P2_7 只驱动，不需要靠切换方向来"读自己写的线"。

DS2482 侧：`AD0` / `AD1` 均接地 → 7 位从机地址 **0x18**（写 `0x30` / 读 `0x31`）；`PCTLZ` 悬空；`IO`（1-Wire）接 `ID_BD` 网络通往 DS2431。

### ⚠ 半字节方向冲突（务必先读）

PCIE-1751 的方向按**半字节（4 bit）**配置，而 **SCL(P2_6) 与 SDA_OUT(P2_7) 落在同一个半字节里**。这带来一个硬约束：

- SDA_OUT 是**推挽**输出，要"释放 SDA"只能把它切成输入（高阻）；
- 但切换的是整个高半字节 —— SCL 会**同时**变成高阻、被 R35 拉高，PC 在此期间**无法驱动 SCL**。

后果：从机拉低 SDA 的所有时刻（每个 ACK 位、每个读数据位）都无法同时做到"释放 SDA + 驱动 SCL"。若图省事让 P2_7 一直保持输出、用输出高表示释放，则从机拉低时会与推挽输出直接对冲，P0_2 读回大概率恒为 1，**ACK 判读和数据读取都会失效**。

**方案 A（推荐，改一根线）**：把 SCL 从 J2 pin 25 移到 Port 2 低半字节的任一脚，例如 **pin 19（P2_0）**。之后 Port 2 低半字节固定输出（SCL）、高半字节在输出/高阻间切换（SDA_OUT）、Port 0 低半字节固定输入（SDA_IN），三者互不干扰，是干净的开漏模拟。DS2482 靠状态寄存器的 1WB 忙标志轮询等待 1-Wire 操作完成，不依赖时钟拉伸，所以 SCL 可以是纯推挽输出。

**方案 B（不改线，纯软件）**：把 Port 2 高半字节整体在两个状态间切换 —— 「输出态」时 SCL 由软件拉低、SDA 由 PC 驱动；「输入态」时 SCL 被 R35 拉高、SDA 交还从机并从 P0_2 采样。读位的采样窗口恰好落在 SCL 高电平期间，时序上是合法的 I²C。代价是 SCL 与 SDA 的释放边沿由同一次方向切换产生、几乎同时发生，理论上存在被从机误判为 START/STOP 的风险，**上线前必须用逻辑分析仪抓波形确认**。

### 其它注意事项

- **电平**：PCIE-1751 与 DS2482 均工作在 5 V，上拉也是 +5 V，电平天然匹配，无需转换。
- **板卡每个 DIO 脚内部自带 10 kΩ 上拉到 +5 V**（手册 P.20「TTL Digital Input/Output」图，为支持干接点输入而设）。这意味着接到总线上的**每一个**板卡引脚都会额外并入一个 10 kΩ 上拉，与背板的 2.2 kΩ 并联：
  - SDA 节点接了 P2_7、P0_2 两个脚 → 等效上拉 = 2.2k ∥ 10k ∥ 10k ≈ **1.53 kΩ**，从机拉低到 0.4 V 需灌 **3.0 mA**；
  - SCL 节点接了 P2_6 一个脚 → 等效上拉 = 2.2k ∥ 10k ≈ 1.8 kΩ，需灌 2.6 mA（由板卡输出级承担，其 24 mA 能力绰绰有余）。
  - I²C 规范对从机的要求是 3 mA @0.4 V，**DS2482 的灌电流已经贴着规范下限、几乎没有余量**。不要再往 SDA 上并更多板卡引脚。
- **JP1 跳线**决定热复位后端口是否保持上次状态；上电默认态下端口为输入，SCL/SDA 被上拉为高，恰好是 I²C 总线空闲态，对 DS2482 是安全的。
- 板卡 +5 V 见 pin 34 / 68（两脚合计 0.5 A），其余 GND 见 pin 9 / 18 / 27 / 29 / 31 / 43 / 52 / 61。

### ⚠ 已知问题：SDA 高电平实测仅 1.9 V

现象：SDA 拆成 IN / OUT 两个脚接到板卡后，总线高电平掉到 **1.9 V**，偶尔能通信但极不稳定。

这个电压两边都不认：DS2482 作为 I²C 器件要求 V_IH ≥ 0.7 × V_CC = **3.5 V**，PCIE-1751 输入要求 V_IH ≥ **2.0 V** —— 1.9 V 对从机是明确的低电平，对板卡输入是灰区。总线在从机眼里近乎一直被拉低，通不了是必然的，"偶尔能通"只是灰区里的运气。

**关键判据**：板卡引脚内部是 10 kΩ **上拉**（见上），并联再多也只会把电平往 +5 V 推，绝不可能把它拉到 1.9 V。所以一定有器件在**主动灌电流拉低**。最符合 1.9 V 这个数值的，是两个推挽驱动器对打：一端 Source 15 mA @2.4 V、另一端 Sink 24 mA @0.4 V，节点被拽到中间偏低的位置，正好落在 1.9 V 附近。

排查顺序：

1. **读回端口方向配置**，确认 Port 0 低半字节（含 P0_2）确实是 **input**。若它仍处于 output 且输出 0，就会和输出高的 P2_7 直接对冲 —— 这是本问题的头号嫌疑，且**纯软件即可修复，无需动硬件**。
2. **拔掉 J2 排线**单独量背板 SDA 对地电压，应为 5 V（R36 上拉）。若拔线后是 5 V、插上变 1.9 V，即可锁定是板卡引脚在拉低。
3. **分别只接 pin 3 / 只接 pin 26**，看是哪一路把电平拽下去。
4. 对冲状态下持续电流可达十几 mA，长期会损伤板卡输出级，排查期间不要长时间保持通电。

**若排查后确认不是软件方向配错**，则用一片 **74HCT07（六路集电极开漏缓冲，非反相）** 做隔离，一次性解决电平和半字节冲突两个问题：

```
P2_6 ──►│ 74HCT07 ├──○── SCL ──┬── DS2482 SCL      (背板 R35 2.2k 上拉)
P2_7 ──►│ 74HCT07 ├──○── SDA ──┼── DS2482 SDA      (背板 R36 2.2k 上拉)
P0_2 ──○┤ 74HCT07 │◄────────────┘                  (板卡内部 10k 上拉即可)
        └─────────┘
        P2_6 / P2_7 各加 10k 上拉到 +5V，防止排线未插时输入悬空
```

- 74x07 是**非反相**开漏：输入 0 → 输出拉低，输入 1 → 输出高阻被上拉为高，软件逻辑与直觉一致，无需取反。
- 隔离后 I²C 总线上只剩 CMOS 输入（<1 µA）和开漏输出，DS2482 拉低只需灌 2.1 mA，余量充足。
- **P2_6 / P2_7 从此永远保持输出态，不再需要切换半字节方向 —— 上一节的半字节冲突随之消失**，方案 A 的改线也不再必要。
- HCT 系列输入门限为 TTL 电平（V_IH = 2.0 V），比 HC 的 3.5 V 宽容，不要用 74HC07 替代。
- 传输延迟约 10~20 ns，对 kHz 级的软件模拟 I²C 毫无影响。

## 位操作的核心逻辑（按方案 A）

```
scl_low()      : Port2 低 nibble 输出，bit0 = 0
scl_high()     : Port2 低 nibble 输出，bit0 = 1        // 推挽直接拉高，DS2482 不做时钟拉伸

sda_low()      : Port2 高 nibble 置输出，bit7 = 0
sda_release()  : Port2 高 nibble 置输入                // 高阻，由 R36 拉高
sda_read()     : 读 Port0，取 bit2                     // 独立读回脚，不受方向切换影响
```

**绝不能**用 SDA_OUT 输出 1 去表示高电平——从机同时拉低时推挽输出会与之直接对冲，且读回值失真。

## 时序与速率的现实约束

- 每次端口读/写都是一次驱动调用 + PCIe 事务，单次开销通常在微秒量级，加上 Windows 非实时调度的抖动，实际 SCL 频率大致在 **数 kHz ~ 数十 kHz**，远低于标准模式的 100 kHz。
- 这对普通 I²C 从设备是安全的：I²C 协议**没有最低时钟频率要求**。但若从设备是 **SMBus** 器件，注意其 25/35 ms 超时会导致总线状态被复位——线程被抢占过久可能触发。
- 位延时用 `QueryPerformanceCounter` 忙等实现，不要用 `Sleep()`（最小粒度太粗）。
- 尽量以**整字节端口读写**替代逐位操作，减少 API 调用次数。
- 建议线程提高优先级，并在时序敏感段内避免日志输出等阻塞操作。

## 软件环境

- Windows + 研华 **DAQNavi / Advantech Device Driver**；安装后可在 *Advantech Navigator* 中看到板卡。
- 编程接口：`Automation.BDaq`（C/C++、C#、.NET 均可），用 `InstantDiCtrl` / `InstantDoCtrl` 读写端口，并通过端口方向属性在输入/输出之间切换。
- 上手顺序建议：先用 Navigator 自带的 DIO 测试面板确认引脚能被正确读写，再写位操作代码；用示波器/逻辑分析仪抓一次完整的 START + 地址字节 + ACK，确认时序无误后再上层协议。
- 板卡编程与 API 的中文资料见 `docs/references/PCIE-1751/`（含 `.chm` 接口手册与《数据采集卡应用与编程》）。

## 目标应用

完整链路为：上位机用 PCIE-1751 的 DIO 模拟出 I²C 主机 → 访问 H-9220 背板上的 **DS2482-100**（U31，I²C ↔ 1-Wire 桥接器，从机地址 0x18）→ 由其经 1-Wire 总线（`ID_BD`）读写 **DS2431** EEPROM。

软件需实现的三层：I²C 位时序 → DS2482 寄存器/命令（Device Reset、Set Read Pointer、1-Wire Reset / Write Byte / Read Byte，配合状态寄存器 1WB 位轮询）→ DS2431 的 1-Wire 命令与暂存器读写流程。
